================================ АЛГОРИТМ ================================

Один круг агента. Каждый шаг отдаёт вход следующему, каждый отсев объясним.

ШАГ 1. ЗАТРАВКА — линтер, бесплатно, детерминированно.
  ruff --no-fix --isolated по всему fedot/, 14 060 указаний, группировка по файлам.
  Ничего не отбрасывать по коду правила. Сейчас is_cosmetic() выкидывает 12 647
  из 14 060 — это решение принимаю я, а не агент, и это неверно: правило говорит
  о форме, а важно последствие. Стоимость показать все: в режиме «файл целиком»
  запрос один на файл и текст файла в нём главный по объёму, лишние строки
  находок почти ничего не добавляют. Убрать префиксный фильтр, оставить его
  только как пометку «линтер считает это косметикой» рядом с находкой.

ШАГ 2. ЧИТАТЕЛЬ — дешёвая модель, параллельно, несколько проходов.
  Вход: исходник файла целиком с номерами строк + ВСЕ находки линтера по нему.
  Выход по каждой находке: live / inert / unclear и одна фраза почему.
    live   — можешь назвать, что сломается и при каких условиях;
    inert  — форма есть, последствия нет;
    unclear— по коду не решить.
  Плюс extra: то, что заметил сам и для чего у линтера правила нет.
  Два независимых прохода, объединение (union_leads.py), расхождение проходов
  само по себе сигнал — файл трудно читается.
  Полнота важнее точности: отсев дальше, и он ничего не стоит.

ШАГ 3. ПРОВЕРЯЮЩИЙ — вердикт выносит интерпретатор, не модель. Три гейта:
  3.1 предсказание: тип исключения назван ДО прогона. Упало другим — опровержение.
  3.2 падение: скрипт запущен в чекауте (PYTHONPATH=repo), ноль на выходе — снято.
  3.3 публичный вход: если скрипт лез во внутренний модуль, обязан повторить
      то же падение через Fedot / FedotBuilder / Pipeline. Не повторил —
      находка внутренняя: путь в коде есть, дойти до него нельзя.
  Замерено: из 9 подозрений читателя выжило 3. Гейт 3.3 снял в том числе
  находку, которую я подтверждал руками, — она через публичный вход даёт
  внятный ValueError, то есть дефекта для пользователя нет.

ШАГ 4. КЛАССИФИКАТОР — кодом, по последствию, не по типу улики.
  критический  — значение принято и не дошло до библиотеки; результат гуляет
                 при фиксированном seed; зависание. invariants.py это умеет.
  обычный      — падение на законном входе, воспроизведённое публичным вызовом.
  косметический— всё остальное. В issue не несём, чинильщику не отдаём.

ШАГ 5. ЧИНИЛЬЩИК — дорогая модель, только критические и обычные.
  Патч + тест, шесть гейтов приёмки. Гейт воспроизведения для проверенного
  дефекта — это повторный запуск скрипта проверяющего, писать новый не нужно.
  Два гейта скрыты от агента намеренно; не показывать.

ШАГ 6. ЖУРНАЛ И ОТЧЁТ. Строка на находку сразу, не в конце. Каждое число в
  отчёте выводимо из журнала.
