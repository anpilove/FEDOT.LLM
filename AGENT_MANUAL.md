# EvolveAgent: устройство и запуск

## Назначение

EvolveAgent ищет локализованные дефекты в FEDOT, доказывает их до патча,
передаёт дорогой модели только подтверждённые случаи и принимает исправление
только после машинных проверок. Это research-конвейер: он готовит ветку,
патчи, тесты и audit, но ничего не публикует автоматически.

## Роли

1. **Затравка:** `ruff --no-fix --isolated` по `fedot/`. Правило линтера —
   только указатель на место, не доказательство дефекта.
2. **Читатель:** `examples/triage_lint.py`, два независимых прохода по полному
   тексту файла. Для каждой находки выдаёт `live`, `inert` или `unclear` и
   может добавить проблему, которой нет в правилах линтера.
3. **Объединение:** `examples/union_leads.py` объединяет оба прохода без
   потери подозрений.
4. **Проверяющий:** `examples/verify_leads.py` превращает подозрение в короткий
   воспроизводящий скрипт. Решение принимает запуск, а не мнение модели.
5. **Классификатор:** код относит подтверждённые последствия к `critical`,
   `ordinary` или `cosmetic`. Неподтверждённые строки получают `excluded`, а
   не маскируются под косметические дефекты.
6. **Чинильщик:** `fedotllm/agents/evolve/loop.py` получает один
   подтверждённый дефект и готовый proof, а GPT-5.4 пишет патч.
7. **Ночной драйвер:** `examples/night_fixer.py` ведёт состояние, журнал,
   бюджет, отдельные audit и отдельный commit на каждый принятый дефект.

## Что делает LLM

- дешёвая модель читает файлы и формулирует проверяемые подозрения;
- дешёвая модель предлагает воспроизводящий скрипт;
- дорогая модель выбирает изменение и пишет патч;
- LLM **не решает**, воспроизведён ли дефект и можно ли принять патч.

## Три гейта проверяющего

1. Модель заранее называет ожидаемый тип исключения.
2. Скрипт должен упасть именно этим исключением в проверяемом checkout с
   `PYTHONPATH=repo`.
3. Внутренний вызов должен повториться через `Fedot`, `FedotBuilder` или
   `Pipeline`. Иначе находка помечается `internal only`.

`confirmed` означает, что пользователь действительно может пройти этот путь.
`refuted`, `internal only` и `not testable` чинильщику не передаются.

## Шесть гейтов чинильщика

1. Proof падает на исходном коде.
2. Патч компилируется, proof после патча проходит.
3. Проходят тесты изменённого модуля и найденных callers.
4. Работает короткий CPU `Fedot.fit`.
5. Runtime probe не показывает ухудшения на скрытых случаях.
6. Для дефекта настраиваемости параметр действительно становится
   настраиваемым, а не отбрасывается.

Проверенный скрипт преобразуется в pytest кодом. Модель не может заменить proof
собственным удобным тестом. Для исходных `KeyError`, `AttributeError` и
`IndexError` новый proof допускает нормальное завершение либо содержательный
`ValueError`/`TypeError`, но не произвольное другое исключение.

## Порядок улик

Ранжирование жёстко задано кодом:

```text
verified public defect
  > measured runtime invariant
  > template proof
  > unverified lint lead
```

Если нет улики, агент делает abstain до запроса патча. Для нескольких дефектов
в одном файле ночной драйвер подаёт их по одному, поэтому первый commit не
блокирует следующий случай из того же файла.

## Запуск одной командой

```bash
export FEDOTLLM_LLM_API_KEY=...
export FEDOTLLM_REPO_PATH=/path/to/FEDOT
export FEDOTLLM_REPO_PYTHON=/path/to/fedot-venv/bin/python

examples/run_pipeline.sh pipeline_out
```

Настройки:

```bash
export FEDOTLLM_CHEAP_MODEL=deepseek/deepseek-v4-flash
export FEDOTLLM_FIXER_MODEL=openai/gpt-5.4
export FEDOTLLM_NIGHT_BUDGET=3
export FEDOTLLM_NIGHT_MAX_FIXES=10
export FEDOTLLM_WORKERS=8
```

Повторный запуск использует готовые `triage1.json`, `triage2.json`,
`leads.json`, `verified.json` и `NIGHT_STATE.json`. Пройденные этапы не
запускаются заново.

## Артефакты

В каталоге запуска:

- `NIGHT_LOG.jsonl` — событие записывается сразу после проверки или попытки;
- `NIGHT_STATE.json` — состояние для возобновления;
- `NIGHT_REPORT.md` — числа, вычисленные из JSON;
- `fixer/<defect>/run/evolution_audit.md` — команды и результаты гейтов;
- `fixes/*.patch` — diff каждого принятого исправления;
- локальная ветка `fedotllm-night-*` — отдельный commit на дефект.

## Фактический контрольный прогон 20 августа 2026

- 9 подозрений после reader/verifier;
- 3 подтверждены через публичный API;
- 3 отсеяны как `internal only`;
- 1 опровергнуто запуском;
- 2 не удалось проверить исполнением;
- все 3 подтверждённых обычных дефекта исправлены;
- чинильщик использовал 9 LLM-запросов и стоил `$0.1643`;
- reader/verifier были переиспользованы из старого запуска без usage-sidecar,
  поэтому их стоимость честно отмечена как не измеренная и не включена;
- тесты FEDOT после патчей: 645 passed, 4 известных падения
  `topological_features`, то есть набор падений совпал с исходным;
- тесты FEDOT.LLM: 221 passed.

## Ограничения

- Линтер даёт места, но не полноту: дефекты без соответствующего правила
  находятся только читателем или runtime-инвариантами.
- Проверяющий ориентирован прежде всего на воспроизводимые падения. Тихие
  ошибки лучше покрываются `invariants.py`.
- Маленький smoke-test и точечные регрессии не заменяют review maintainer.
- Старые артефакты без `*.usage.json` нельзя включать в точную стоимость.
- Ветка остаётся локальной: push и публикация в `aimclub/FEDOT` не выполняются.
# EvolveAgent: как он устроен и что от него ждать

Фоновый агент, который сам ищет дефекты в `aimclub/FEDOT`, доказывает их
запуском и присылает патч с падающим тестом. Работает по одному репозиторию,
поэтому знает его особенности и может запускаться регулярно.

---

## Алгоритм

Четыре роли и приёмка без модели. Каждая ступень отдаёт вход следующей, и
каждый отсев объясним не мнением, а фактом.

```
ruff, 14 364 указания                      бесплатно, детерминированно
   │  ничего не отбрасывается по коду правила
   ▼
ЧИТАТЕЛЬ  deepseek-v4-flash, 2 прохода     ~$0.04 за проход по 207 файлам
   │  файл целиком + все находки линтера по нему
   │  выход: live / inert / unclear по каждой находке + свои подозрения (extra)
   ▼
ПРОВЕРЯЮЩИЙ  deepseek-v4-flash             центы
   │  три гейта, вердикт выносит интерпретатор
   ▼
КЛАССИФИКАТОР  без модели                  бесплатно
   │  критический / обычный / косметический
   ▼
ЧИНИЛЬЩИК  gpt-5.4, только 1–2 класс       $0.02–0.05 за круг
   │  патч + тест
   ▼
ПРИЁМКА  шесть гейтов, без модели          бесплатно
```

### Ступень 1 — линтер как затравка

`ruff --no-fix --isolated`, все правила. Раньше 12 658 находок из 14 364
отбрасывались по префиксу правила — это было решение человека, а не агента, и
оно неверно: правило описывает форму, а важно последствие. Теперь агенту
показывают всё, стилистические помечены как стилистические, решает он.

Это почти ничего не стоит: в режиме «файл целиком» запрос один на файл, текст
файла в нём главный по объёму, а находка — одна строка.

### Ступень 2 — читатель

Видит исходник целиком с номерами строк. Отвечает по каждой находке линтера и
добавляет свои. Два независимых прохода, объединение по `(файл, строка)`.

Замерено на полном репозитории: проходы дали 131 и 152 подозрения, а сошлись
только на 36. Второй проход — не дубликат, он почти удваивает материал.

### Ступень 3 — проверяющий: четыре гейта

1. **Предсказание.** Тип исключения назван ДО прогона. Упало другим —
   опровержение, не успех. Без этого скрипт с опечаткой засчитывался бы за дефект.
2. **Падение.** Скрипт запускается в чекауте под проверкой с
   `PYTHONPATH=repo` — иначе `import fedot` молча берёт то, что стоит в
   site-packages. Ноль на выходе — подозрение снято.
3. **Место падения.** Трассировка обязана называть тот файл, про который
   подозрение. Замерено: 4 подтверждения из 11 падали совсем в другом месте —
   в одном скрипт написал `Fedot(task=...)`, хотя параметр называется
   `problem`, и `TypeError` прилетел из конструктора. Тип совпал, файл был ни
   при чём.
4. **Публичный вход.** Если скрипт лез во внутренний модуль, он обязан
   повторить то же падение через `Fedot` / `FedotBuilder` / `Pipeline`. Не
   повторил — путь в коде есть, дойти до него нельзя.

Гейт 4 сначала сделали суждением модели. **Не работает:** три прогона по одним
и тем же девяти подозрениям дали 6 «да», 3 «нет», снова 6 «да», причём один
отказ сослался на проверку, которой в коде нет. Заменён на механику — точное
сравнение списка публичных модулей плюс повторный запуск; два прогона подряд
совпали до строки.

### Ступень 4 — классификатор

| класс | признак | пример |
|---|---|---|
| критический | значение принято и не дошло до библиотеки; результат гуляет при фиксированном seed; зависание | `PolyfitImplementation` молча переписывает переданный `degree` |
| обычный | падение на законном входе, воспроизведённое публичным вызовом | `Fedot(problem='чушь')` → голый `KeyError` |
| косметический | всё остальное | формулировка сообщения |

Чинильщику отдают только первые два.

### Ступень 5 — чинильщик и приёмка

Шесть гейтов. Главный — тест обязан падать **до** патча. Для проверенного
дефекта тест строится кодом из скрипта проверяющего, модель к нему не
прикасается.

Устройство теста тоньше, чем кажется, и это выяснилось на живом круге. Первая
версия требовала, чтобы скрипт отработал без исключения — и забраковала
правильный патч: дефект «падает с невнятной ошибкой» чинится тем, что падение
остаётся, но становится внятным. Теперь тест требует исчезновения **именно
того** исключения, которое наблюдал проверяющий. Честный предел: машина не
судит, стало ли новое сообщение хорошим.

Два гейта скрыты от агента намеренно — зонд рантайма и гейт настройки. Дважды
измерено, что патч проходил все видимые проверки и делал хуже.

## Что он находит и чего не находит

**Находит.** Параметр принят и молча перезаписан. Обещание документации не
выполнено. Падение на законном, но неудобном входе. Невнятная диагностика там,
где ошибка пользователя ожидаема.

**Не находит.** То, до чего нельзя дойти публичным вызовом — отбрасывается
намеренно. Плохое качество нового сообщения об ошибке — механически не
проверяется. Дефекты, где причина в другом файле и связь возникает только в
рантайме (реестр, JSON с параметрами, кэш) — чтением не берутся, их находит
отдельный детерминированный скан по 79 операциям.

**Сознательно не делает.** Не расширяет сетку прогонов по операциям (3%
покрытия строк, источник исчерпан). Не расширяет правила линтера: из 40 находок
`RUF012` спящими оказались 39.

## Как запустить

```bash
export FEDOTLLM_LLM_API_KEY=$(cat ~/.config/fedotllm/or_key2)
export FEDOTLLM_REPO_PATH=/путь/к/чекауту/FEDOT
examples/run_pipeline.sh
```

Линтер, два прохода читателя, объединение, проверяющий, чинильщик, отчёт.
Полезные переменные: `FEDOTLLM_MAX_FIXES` (по умолчанию 10),
`FEDOTLLM_WORKERS` (по умолчанию 8), `FEDOTLLM_FIX_MODEL`.

Отдельные ступени:

```bash
python examples/triage_lint.py --whole-file --workers 8   # читатель
python examples/union_leads.py p1.json p2.json            # объединение
python examples/verify_leads.py --leads leads.json        # проверяющий
python examples/night_report.py --out pipeline_out        # отчёт
```

## Тесты

```bash
uv run python -m pytest tests/unit -q     # 220
```

Регрессия FEDOT: полный `test/unit` до и после патчей — набор падений обязан
совпасть с нетронутым деревом.
